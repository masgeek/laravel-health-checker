# Repository guidance

- This is a standalone Composer library, not an application. Keep framework-facing code under `src/` and preserve PSR-4 namespace `Masgeek\HealthCheck\` mapped from `src/`.
- `HealthCheckServiceProvider` is the integration point: Laravel auto-discovers it, merges `src/config/healthcheck.php`, loads `/health`, and registers the `health:check` command in console contexts.
- Consumers publish configuration with `php artisan vendor:publish --tag=healthcheck-config`; update `config/healthcheck.php` in the consuming application to enable or disable individual checks.
- The default endpoint is `GET /health`; it returns HTTP 200 only when all enabled checks are `UP`, otherwise HTTP 500. It is rate-limited by default and returns only check statuses; set `HEALTHCHECK_EXPOSE_DETAILS=true` only for trusted monitoring access. The command is `php artisan health:check` (or `php artisan health:check --json`); it returns exit code 0 when healthy and 1 otherwise.
- Health-check orchestration and integration-specific behavior live in `src/Services/HealthCheckService.php`; keep the public result shape (`status`, ISO-8601 `timestamp`, and `checks`) compatible with the controller and command.
- Checks have real side effects or external prerequisites: cache and storage checks write temporary data, logging writes to `storage/logs/health_check.log`, database/migrations access the configured DB schema, and Redis/Loki require configured services. Do not treat a failed optional external check as a local code failure.
- `src/config/healthcheck.php` uses `env()` defaults; `redis`, `mail`, and `loki` are disabled by default, while database, cache, queue, migrations, environment, storage, disk-space, and logging are enabled.
- Run the package test suite with `composer test` or `vendor/bin/pest`; run `composer analyse` for PHPStan and `composer lint` for PHP-CS-Fixer before submitting changes. Also run `composer validate` and syntax-check PHP files with `php -l` (or the project’s available CI equivalent).
- Dependency updates are managed by Renovate; release automation promotes `develop` to `main` and tags/releases from `main`. Do not change those workflow conventions as part of feature work.
